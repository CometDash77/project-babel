# M01 · 音频获取与预处理选型调研

调研日期：2026-09-25。本稿供 [M01 选型拍板票](https://github.com/CometDash77/project-babel/issues/35)使用，**不指定主选或备选**。目标输入是英文长播客，输出应包含可追溯的原始媒体、供后续 M02–M06 使用的工作音频，以及每个片段相对于原节目的绝对时间。以下是资料调研；未下载节目、安装候选工具或运行两小时音频实验。许可讨论只涉及工具代码，不能代替节目内容授权。

## 证据基底与比较口径

- [M01 既有模块调研](../research/01-acquisition-preprocessing.md)已核对候选功能、限制和实验缺口；[成熟一条龙项目反查](00-mature-pipeline-stack.md)记录了真实成品流程：pyVideoTrans 用 FFmpeg 提取工作音频，VideoLingo 用 yt-dlp 与 FFmpeg，SoniTranslate 接收 URL／本地文件并用 yt-dlp。这些是**入口组合有成品先例**的证据，不证明两小时多人播客可稳定处理。[pyVideoTrans 架构](https://github.com/jianchang512/pyvideotrans/blob/main/docs/architecture.md)、[VideoLingo 介绍](https://github.com/Huanshere/VideoLingo/blob/main/docs/pages/docs/introduction.zh-CN.md)、[SoniTranslate README](https://github.com/R3gm/SoniTranslate)。
- 热度与维护数字取自 2026-09-25 的 GitHub [仓库 API](https://docs.github.com/en/rest/repos/repos#get-a-repository) 和 release 页快照。star、最近推送和 issue 数只能提示社区规模及活动；`open_issues_count` 包含 PR，不能据此推断缺陷率或响应时限。真正的本项目成功率**需要实验确定**。
- 候选按输入／处理职责比较。RSS feed、受站点规则约束的 URL、已有本地文件不是同一种入口；不同职责的工具不应仅按 star 排序。本句为本项目的比较口径推论，依据是 [podcast-dl 的 RSS 输入契约](https://github.com/lightpohl/podcast-dl#options)、[yt-dlp 的站点提取说明](https://github.com/yt-dlp/yt-dlp/blob/master/README.md)和 [FFmpeg 的媒体处理文档](https://ffmpeg.org/ffmpeg.html)。

## 建议交给拍板票的接口与启动前门槛

1. **原件与工作副本分存。** 原件附来源 URL、RSS GUID／站点 ID、取得时间、工具及版本、哈希、媒体轨道、声道、采样率和时长；工作副本记录每步参数和父文件哈希。切片保存原节目绝对起止时间与样本偏移。此为本项目接口推论，依据是 [FFmpeg/ffprobe 的探测与裁切能力](https://ffmpeg.org/ffprobe.html)、[M04 时间轴需求](../research/04-asr-timeline.md)和 [M06 声学需求](../research/06-prosody.md)，现成工具未承诺完整提供。
2. **不把独立切片标准化当默认步骤。** 若需要响度工作副本，先测整集并保留原件、IL/LRA/true-peak 和实际输出统计；跨片强弱与 M05/M06 情绪声学特征是否受影响**需要实验确定**。[FFmpeg loudnorm](https://ffmpeg.org/ffmpeg-filters.html#loudnorm)、[ffmpeg-normalize 统计](https://github.com/slhck/ffmpeg-normalize)。
3. **获取验收：**选获准使用的 RSS、站点 URL、直接媒体 URL 和本地文件各一组，包含长节目、重定向和异常 feed；核对重试/恢复、来源信息、哈希、实际音轨及时长。下载成功率、Windows/Linux 差异、特定站点访问限制**需要实验确定**。[podcast-dl 归档/重试](https://github.com/lightpohl/podcast-dl#options)、[yt-dlp EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS)。
4. **预处理验收：**用含音乐、静音、多人重叠及已知时间标记的长节目，比较原件、双遍标准化副本与裁切副本的 IL/LRA/true-peak、听感、首尾误差、声道和跨片绝对时间；记录两小时 CPU 时间、峰值内存/磁盘和中断恢复。所有效果、参数阈值与资源需求**需要实验确定**。[FFmpeg seek](https://ffmpeg.org/ffmpeg.html#Main-options)、[loudnorm](https://ffmpeg.org/ffmpeg-filters.html#loudnorm)。

**留待 M01 grilling 票确认：**各输入来源的主选/备选分配、工作音频格式和声道、是否标准化及目标响度、切片策略和可接受的绝对时间误差。本 research 票只提供候选与证据；没有将文档示例或 release 活跃度外推成两小时成功率。
